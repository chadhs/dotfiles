# OBS Setup — Omarchy / FFXIV + Multi-Game Recording

Last verified: 2026-09-13 (updated for Battle.net desktop entries)
Machine: Omarchy (Arch), Wayland/Hyprland, RTX 4060, dual 4K@60 monitors
Workflow: record gameplay clips → edit in ScreenFlow (Mac) → upload to YouTube at 1440p60

## Restore Procedure (fresh machine)

1. Install OBS and plugins (native Arch packages):

   ```
   yay -S obs-studio obs-vkcapture lib32-obs-vkcapture obs-pipewire-audio-capture
   ```

2. Copy the config back:

   ```
   cp -a obs-studio-config/. ~/.config/obs-studio/
   ```

3. Restart OBS. All profile, encoder, scene, and plugin settings return as documented below.
4. Re-apply the per-launcher game capture settings below (those live outside OBS config).

Backup excludes `logs/` and `profiler_data/` (auto-regenerated by OBS).

## Video

| Setting | Value |
|---|---|
| Base (Canvas) Resolution | 3840x2160 |
| Output (Scaled) Resolution | 2560x1440 |
| Downscale Filter | **Bicubic** |
| FPS | 60 |

Decisions behind this:

- Output = delivery resolution (YouTube uploads are 1440p60). Capturing 4K for a 1440p
  deliverable only cost file size (8 GB per 3-min clip at 4K vs ~1.2 GB at 1440p).
- **Lanczos is deliberately NOT used.** On DLSS/FSR-upscaled game frames it rings/over-sharpens
  ("loud" look). Bicubic is the tested, approved filter. Area is softer still (tested, too soft).
- Downscaling is cheaper than recording 4K (2.25x fewer pixels for the encoder to chew on);
  the scale itself is a trivial GPU pass. Game FPS is unaffected.

## Encoder (Recording → Advanced)

| Setting | Value |
|---|---|
| Video Encoder | NVIDIA NVENC HEVC |
| Rate Control | **Constant QP (CQP) 22** |
| Keyframe interval | 0 (auto) |
| Preset | P5: Slow (Good Quality) |
| Tuning | High Quality |
| Multipass Mode | Two Passes (Quarter Resolution) |
| Profile | main |
| Look-ahead | OFF |
| Adaptive Quantization | ON |
| B-Frames | 2 |
| B-Frame as Reference | Disabled |

- **GOTCHA:** Switching the Video Encoder resets Rate Control to Constant Bitrate 10,000 Kbps.
  After ANY encoder change, re-verify: Rate Control = CQP, value 22, Look-ahead off.
- CQP semantics: **lower number = higher quality = bigger files.** 18 = higher fidelity step,
  20 = original target, 22 = current sweet spot, 24+ = smaller/softer.
- FFXIV at 4K pushed CQP 20 to ~320 Mbps (8 GB/3.5 min). 1440p + CQP 22 is the fix.
- Fallback if sizes ever spike again: VBR Constrained, target 30 Mbps / max 60 Mbps at 1440p60
  (above YouTube's recommended 1440p60 upload bitrate — no perceptible delivery loss).

## Format / Audio

- Recording format: **Matroska (.mkv)** with OBS **auto-remux to MP4** (crash-safe + ScreenFlow-ready).
- Housekeeping: after each recording the `.mkv` twin remains next to the `.mp4` — delete the
  `.mkv` (remux is lossless; the mp4 is the full recording).
- Audio Encoder: FFmpeg AAC, 192 kbps, Track 1 only (no mic in the setup).
- Recording path: `~/Videos/OBS`.

## Replay Buffer

- Enabled, Maximum Replay Time 300 s, Maximum Memory 8192 MB.
- Fine at current bitrates (~1–2 GB per 5 min worst case).

## Game Capture (per launcher)

The obs-vkcapture plugin registers an **implicit Vulkan layer** gated on env var `OBS_VKCAPTURE`.
The layer is always visible to Vulkan apps; the env var turns capture on.

| Game | Launcher | Setting |
|---|---|---|
| Enshrouded | Steam | Launch Options: `obs-gamecapture %command%` |
| Guild Wars 2, Soulframe | Lutris | Configure → System options → Command prefix: `obs-gamecapture` |
| FFXIV | XIVLauncher | Settings → Game → Additional Game Arguments: `OBS_VKCAPTURE=1 %command%` |
| Battle.net (WoW etc.) | Omarchy entry `battlenet.desktop` | Exec: `env OBS_VKCAPTURE=1 omarchy-launch-battlenet` |
| Battle.net (WC3 CertFix) | Omarchy entry `battlenet-wc3fix.desktop` | Exec: `env OBS_VKCAPTURE=1 ~/.local/bin/omarchy-launch-battlenet-wc3fix` |
| Ashes of Creation | Omarchy entry `evolve-companion.desktop` | Exec: `env OBS_VKCAPTURE=1 /home/chadhs/Games/EvolveCompanion-linux-amd64` |

Critical details:

- The variable is **`OBS_VKCAPTURE=1`** — NOT `ENABLE_OBS_VKCAPTURE=1` (a wrong name cost a
  debugging session; `ENABLE_*` is silently ignored by the Vulkan loader). Verify against
  `/usr/share/vulkan/implicit_layer.d/obs_vkcapture_64.json` → `enable_environment`.
- XIVLauncher's argument field cannot wrap programs ("Can't pass programs"), but env vars in
  Steam convention (`VAR=value %command%`) work — that is why FFXIV uses the bare env var.
- FFXIV needs **DXVK enabled** in XIVLauncher's WINE tab (game renders via Vulkan through DXVK).
- The `obs-gamecapture` wrapper is harmless when OBS is closed — set it once per game and forget it.
- Order: **start OBS first, then launch the game.**
- **AoC (Evolve Companion) GOTCHA:** the companion spawns the game itself, so Steam launch
  options never reach `AOCClient-Win64-Shipping.exe`. The env var must live on the
  **companion's desktop entry Exec line** (done above) so Proton's child inherits it.
  Observe on Steam app 4124950, Proton Experimental, no EAC (`eac_deployment_id="none"`).

## Audio

- Game audio: **Application Audio Capture (PipeWire)** source → picks the running game process.
  Keeps Discord/browser/notification audio out of recordings.
- Screen Capture (PipeWire) exists as a fallback capture method (window/monitor scoped) but the
  Vulkan Game Capture source is preferred for games (no portal prompts, no alt-tab leakage).

## Troubleshooting

- **Game Capture dropdown empty / game not listed:**
  1. Verify the env var reached the game process:
     `tr '\0' '\n' < /proc/$(pgrep -f <game-binary> | head -1)/environ | grep OBS`
     Expect to see `OBS_VKCAPTURE=1`.
  2. Verify OBS saw the capture: `~/.config/obs-studio/logs/` — search for `Client connected`.
  3. Verify the source is actually the vkcapture "Game Capture" source, NOT a Screen Capture
     (PipeWire) source renamed "Game Capture" — PipeWire properties show a
     "Window: Capture any window" dropdown; vkcapture properties show an application list.
  4. Confirm the game renders via Vulkan (DXVK active, not WineD3D/GL).
  5. Fallback: window-scoped Screen Capture (PipeWire).
- **Encoder settings look wrong after a change:** see the encoder GOTCHA above; check
  `~/.config/obs-studio/basic/profiles/Untitled/recordEncoder.json` — it stores only
  non-default keys (e.g. `{"rate_control":"CQP","lookahead":false}`).
- **File size sanity:** ~25–40 GB/hour expected at 1440p60 CQP 22 on FFXIV-like content.
  Sudden doubling = rate control reverted to CBR or CQP value changed.
